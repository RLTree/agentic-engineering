## Why this exists

A weak agentic request often asks a model to be “robust,” “professional,” “production-ready,” or “data-driven” while leaving product evidence, representative use, state, permissions, stop conditions, recovery, lifecycle decisions, verification, and deliverables implicit.

This plugin gives Codex the vocabulary and decision procedures to:

1. place each control in the specification, context, harness, loop, graph, runtime, repository, product workflow, lifecycle gate, or human boundary that can enforce it;
2. expose an agentic product to representative consequential work early without making production an uncontrolled experiment;
3. join task, trajectory, effect, outcome, intervention, recovery, and human-work evidence;
4. convert observed failures, near misses, successes, and workarounds into product, eval, tool, policy, architecture, and system-constraint changes;
5. carry evidence and decision continuity from discovery through retirement;
6. implement typed, observable, recoverable agent applications in Rust.

## Central decision model

Use the smallest architecture and the lowest-risk evidence method that can answer the current question.

```text
Architecture:
direct call → deterministic workflow → bounded loop → explicit graph → durable workflow → multi-agent

Authentic-use exposure:
replay/offline → observe-only → shadow/silent → recommendation-only → approval-gated → bounded autonomy → broader autonomy

Product lifecycle:
discover ↔ validate ↔ specify ↔ architect/plan ↔ construct/verify ↔ secure/release
         ↔ operate/SRE ↔ experiment/learn ↔ maintain ↔ retire
```

Every escalation must name the requirement or uncertainty that the simpler form cannot satisfy. Evidence is valid only for the operating envelope observed.

## High-value invocations

### Controlled authentic use

```text
Use $authentic-use-engineering to design the smallest safe controlled field-learning program for this product. Define the representative workload, operating envelope, autonomy/exposure ladder, decision rights, task/trajectory/effect/outcome/intervention evidence, privacy and sampling policy, severe-event stop rules, review cadence, and observation-to-product/eval/tool/policy change loop.
```

### Full-lifecycle assurance

```text
Use $agentic-product-lifecycle to tailor the lifecycle to this product and produce a Lifecycle Assurance Plan. For discovery, feasibility, requirements, architecture, construction, secure release, production/SRE, experimentation, maintenance, and retirement, name the decision, owner, artifact, evidence, readiness threshold, feedback path, and stop/revisit trigger.
```

### Rust field observability

```text
Use $rust-agent-observability with $rust-agent-runtime and $rust-agent-durability to define typed run/task/action/effect/exposure/observation identities, tracing and OpenTelemetry propagation, privacy/cardinality/sampling policy, ambiguous-effect evidence, human intervention signals, rollout gates, and verification tests.
```

### Cross-layer routing

```text
Use $agentic-engineering to diagnose the responsible control and lifecycle layers, choose the smallest fitting topology, and compose only the focused skills whose decisions remain consequential.
```

## Trust and limitations

The package does not widen the host sandbox, credentials, permissions, or approval policy. Rust files are adaptable reference fragments rather than a supported crate. The release environment lacked a live Codex/GPT-5.6 Sol runner and Cargo/rustc, so the blind model-transfer and Rust compilation protocols are included but not falsely marked as executed. Product impact also depends on representative access, trustworthy outcome labels, correct skill activation, repository quality, domain review, and organizational follow-through.

See `CONFIDENCE.md`, `EVALUATION.md`, `PLUGIN-DESIGN-BRIEF.md`, and `evals/results/release-report.json`.
