# Design Systematize

Capture a successful world after it has earned reuse. Do not use tokens or documentation to legitimize an unproven direction.

## Entry gate

Run only when:

- the selected world has been implemented and verified;
- at least one consequential surface demonstrates it;
- another surface or team will consume the system;
- the user approves durable capture.

## Produce

1. `DESIGN.md`: thesis, audience, use scene, structural grammar, salience, material/type/motion commitments, responsive behavior, and explicit exceptions.
2. DTCG-compatible primitive, semantic, and component tokens with aliases and descriptions.
3. Pattern records containing purpose, use conditions, avoid conditions, source artifact, counterexample, and last validation date.
4. Interaction contracts for repeated behaviors.
5. Exception ledger for deliberate deviations.

## Preserve evidence

A pattern is reusable only when its source artifact and relevant states remain identifiable. Record what was actually validated and what remains a hypothesis. A token serializes a choice; it does not prove the choice is good.

## Keep it small

Capture only decisions that recur or must remain consistent. Surface-local composition stays in the surface brief. Do not convert every CSS value, one-off flourish, or implementation detail into system authority.

Return the durable files and a short list of intentionally uncaptured local decisions. The parent owns package integrity and supersession.
