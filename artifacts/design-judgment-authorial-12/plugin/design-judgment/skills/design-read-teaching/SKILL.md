# Read and Teaching

Design the learning sequence, not a documentation shell with a quiz attached.

```text
question → explanation → mechanism-revealing example → practice → feedback → return to reading
```

- Start from the reader's real question and prior knowledge.
- Give each section one teaching job; use headings that carry the conceptual progression.
- Place examples where the mechanism becomes visible, not in a detached gallery.
- Make glossary and supporting detail available without forcing expert readers through it.
- Practice should require retrieval or application, not recognition of a phrase just shown.
- Feedback explains why an answer works, what misconception it reveals, and where to resume.
- Progress and active-section indicators must reflect the reader's actual position after scrolling settles.
- Preserve focus, location, and reading state when entering or leaving examples, glossary, or practice.
- Narrow layouts should transform navigation and support rails rather than compressing them beside the text.

Use editorial character to make the material inviting, but keep the lesson—not the interface—at the center.
