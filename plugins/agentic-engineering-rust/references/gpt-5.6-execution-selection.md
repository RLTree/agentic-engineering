# GPT-5.6 Execution Selection

Keep one lean outcome contract across Luna, Terra, and Sol. Change model, reasoning, and orchestration configuration more often than prompt language.

| Configuration | Use when | Contract emphasis |
|---|---|---|
| Luna | narrow, high-volume, easy-to-grade work | schema, literal rules, missing-data behavior, one check |
| Terra | routine engineering and analysis | result, material constraints, verification, final evidence |
| Sol | ambiguous or high-value judgment | domain context, invariants, authority, evidence, completion bar |
| Sol + Max | difficult single-thread reasoning | same contract; compare measured gain against lower effort |
| Sol + Ultra | genuinely independent streams | root authority, disjoint ownership, worker evidence, fan-in |
| Pro mode | marginal quality materially matters, one final answer | same contract; compare quality, latency, and cost |
| Programmatic Tool Calling | bounded tool-heavy transformation without fresh judgment between calls | eligible tools, schema, retry/stop budget, direct handoff |

Do not ask the prompt to simulate a mode. Configure the mode and evaluate it on representative work. Lean prompts, relevant tools, and explicit autonomy boundaries generally outperform repeated procedural scaffolding.

Evidence basis: R128.
