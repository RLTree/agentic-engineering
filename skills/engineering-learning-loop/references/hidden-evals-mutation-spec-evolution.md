# Hidden Evals, Mutation, and Specification Evolution

Visible cases improve iteration but invite overfitting. Consequential skill or policy changes should combine:

1. **visible development cases** for fast diagnosis;
2. **held-out cases** unknown to the authoring loop;
3. **negative controls** that should not activate or change behavior;
4. **semantic mutations**—plausible faulty variants the suite should reject;
5. **specification evolution**—changed requirements that preserve unaffected behavior;
6. **baseline comparison** without the proposed intervention.

Score activation, following, composition, recovery, verified outcome, authority compliance, safety, and efficiency independently. A high visible pass rate with weak mutation or held-out performance is not adoption evidence.
